The OSI Reference Model

The Open Systems Interconnection (OSI) model is a conceptual framework for discussing network communication. It separates responsibilities into seven layers. It is useful for learning, design, and troubleshooting; it is not a requirement that every real protocol implement seven separate software modules. The layers are commonly numbered from 1 at the bottom to 7 at the top.

Layer 1, Physical, carries raw bits over a medium. It concerns electrical, optical, or radio signals, connectors, frequencies, timing, and link speed. A damaged cable, incorrect transceiver, interference, or disabled radio can cause a Layer 1 problem. Physical equipment includes cables, antennas, repeaters, and the signal functions of network interfaces.

Layer 2, Data Link, transfers frames across one local link. It uses link-local identifiers such as Ethernet MAC addresses, defines frame boundaries, and may detect transmission errors. Ethernet and Wi-Fi are common examples. Switches primarily forward frames at this layer. A switch learns which MAC addresses are reachable through its ports and forwards a unicast frame toward the learned port; an unknown destination may be flooded within the VLAN.

Layer 3, Network, moves packets between IP networks. Logical addresses identify source and destination networks, and routers use routing information to select a next hop. IPv4 and IPv6 operate at this layer. A host uses its subnet prefix to decide whether a destination is local; for a remote destination it sends the packet to a default gateway. Routers can decrement a packet's hop limit or time-to-live as they forward it.

Layer 4, Transport, provides communication between processes on hosts. TCP provides a reliable, ordered byte stream with acknowledgements, retransmission, flow control, and congestion control. UDP sends independent datagrams with less built-in overhead and no delivery guarantee. Port numbers identify application endpoints. A firewall rule that allows an IP address but blocks the required transport port can still prevent an application from connecting.

Layers 5, 6, and 7 describe communication above transport. The Session layer coordinates dialogs and sessions in the OSI model. The Presentation layer describes data representation, character encoding, compression, and encryption. The Application layer provides network services to software, such as web, name-resolution, and email protocols. Real protocol suites often combine responsibilities from these three layers. For example, TLS provides security used by applications rather than mapping neatly to only one OSI layer.

Encapsulation helps explain how the model works. An application creates data; transport adds a port-based header; the network layer adds IP addressing; the data-link layer adds local-link framing; and the physical layer sends signals. The receiver processes the incoming information in reverse. A router normally removes the incoming link frame and creates a new frame for the next link while forwarding the IP packet.

The model also offers a troubleshooting vocabulary. If no carrier or wireless association exists, investigate physical connectivity. If a host cannot reach another device on the same VLAN, check the local link, VLAN membership, and MAC learning. If local communication works but remote networks fail, inspect IP addressing, gateway configuration, and routing. If a server is reachable but one service is not, check transport ports, firewall policy, and the application. Layer boundaries are a diagnostic aid, not proof that a fault belongs to only one layer.
