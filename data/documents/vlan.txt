Virtual LANs (VLANs)

A virtual local area network (VLAN) divides a switched Ethernet infrastructure into separate Layer 2 broadcast domains. Devices in different VLANs do not exchange ordinary Ethernet broadcasts as if they were on one LAN. VLANs are configured logically on switches, so separate groups can use the same physical switching equipment. They are commonly used to organize users, servers, voice devices, and management traffic, and to limit the scope of broadcast traffic.

A VLAN is not automatically an IP subnet, a firewall, or a complete security boundary. A common design assigns one IP subnet to each VLAN, but this is an administrative convention rather than a protocol requirement. Devices in different VLANs generally need a Layer 3 router or multilayer switch to communicate. Inter-VLAN routing is also the point where access-control lists or firewall policies can allow, restrict, and log traffic between groups.

An access port normally carries traffic for one configured VLAN and sends or receives untagged Ethernet frames for an endpoint. A trunk port carries traffic for multiple VLANs between network devices. IEEE 802.1Q inserts a VLAN tag into Ethernet frames on a trunk so the receiving switch can identify the VLAN. The tag includes a VLAN identifier; the receiving configuration must permit that VLAN on the trunk. A native VLAN may carry untagged traffic on some trunk configurations, so both ends should agree on the native VLAN and unused VLANs should not be treated as trusted.

VLAN membership may be configured statically per switch port or assigned through authenticated access-control systems. A port placed in the wrong VLAN can give a device the wrong address, gateway, or access policy. A mismatch in the allowed VLAN list on trunk endpoints can make only some networks fail. Switches learn MAC addresses per VLAN, so the same MAC address can be learned in different VLAN contexts.

A small example illustrates the roles: employee workstations can occupy VLAN 10 and use subnet 192.168.10.0/24, while servers occupy VLAN 20 and use subnet 192.168.20.0/24. The numbers are local design choices, not universal reserved meanings. If a workstation needs an application on the server network, the Layer 3 gateway routes the traffic between the subnets. A policy can allow the required service while denying unrelated connections. Simply creating two VLANs does not enforce such a Layer 3 policy by itself.

Good VLAN operations use a documented VLAN-to-subnet plan, consistent trunk configuration, explicit access-port assignments, and monitoring. Administrators should disable unused ports or place them in an isolated unused VLAN, restrict which VLANs cross trunks, and protect management interfaces. Native VLAN settings and trunk negotiation should be configured deliberately. Troubleshooting checks the endpoint's port, VLAN assignment, MAC learning, DHCP scope, subnet and gateway, trunk allowed list, and inter-VLAN routing policy.

VLANs can improve organization and reduce broadcast scope, but they do not encrypt Ethernet traffic. An attacker with access to a switch port may still attack devices in the same VLAN, and a configuration error can bridge traffic unexpectedly. Security depends on authenticated access, switch hardening, Layer 3 filtering, monitoring, and correct configuration in addition to segmentation.
