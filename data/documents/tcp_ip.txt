TCP/IP and Transport Protocols

TCP/IP is the protocol suite used for communication across the Internet and many private networks. A common teaching model has four layers: Link, Internet, Transport, and Application. The Link layer handles communication on the local medium, the Internet layer provides IP addressing and packet forwarding, the Transport layer provides host-to-host process communication, and the Application layer contains protocols used by software. This model groups some OSI layers together; the two models are related but their layers do not match one-to-one in every implementation.

TCP (Transmission Control Protocol) is connection-oriented. Before application data is exchanged, the endpoints normally establish state using a three-way handshake: the client sends SYN, the server responds with SYN-ACK, and the client returns ACK. Sequence numbers and acknowledgements help TCP deliver a reliable, ordered byte stream. Lost data can be retransmitted. TCP also uses a receive window for flow control and congestion-control algorithms to adapt sending to network conditions. Reliability adds state and traffic, so TCP is not simply a faster or slower version of UDP.

UDP (User Datagram Protocol) is connectionless and sends independent datagrams. It does not guarantee delivery, order, or duplicate suppression at the transport layer. Its smaller transport header and lack of a built-in handshake can be useful for latency-sensitive applications, simple queries, and protocols that implement their own reliability. Applications using UDP must tolerate loss or add the recovery behavior they need. DNS commonly uses UDP for ordinary queries, while some DNS operations use TCP; modern applications may also build reliable transports over UDP.

Port numbers identify transport-layer endpoints on a host. A connection is commonly distinguished by protocol plus source and destination IP addresses and ports. A server listens on a configured port; a client usually receives a temporary source port. A firewall or access-control list must permit the appropriate protocol and direction. Knowing that a host responds to ping is not enough to prove that a TCP service is listening or reachable.

IP delivers packets on a best-effort basis: it can forward them without promising that they arrive, arrive once, or arrive in order. Routers choose paths independently for packets, and congestion or link failure can result in delay or loss. TCP can recover from some loss at the endpoints, but the application still experiences added delay. UDP applications may use their own sequence numbers, acknowledgements, or forward-error correction when they require such behavior.

Application protocols define useful exchanges. DNS translates names to records such as addresses. HTTP defines request and response messages for web services; HTTPS is HTTP protected by TLS. TLS authenticates a server through certificates and encrypts traffic in transit when configured and validated correctly. Encryption in transit does not hide all metadata, prevent a compromised endpoint from reading data, or guarantee that a website is trustworthy. Email and file-transfer protocols have their own ports and security options.

Encapsulation proceeds down the stack: application data is carried in a TCP segment or UDP datagram, which is carried in an IP packet, which is carried in a link-layer frame. Each network interface processes the frame for its local link. A router forwards the IP packet and wraps it in a new frame for the next link. This layered design allows an application to communicate across different link technologies without needing to implement each physical network.
