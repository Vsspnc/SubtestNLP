IP Routing

Routing is the process of selecting a path for an IP packet to reach a destination network. A router examines the destination IP address and consults its routing information. A route normally contains a destination prefix, a next hop or outgoing interface, and possibly a metric or administrative preference. The router forwards a packet to the next hop; it does not need to know the complete end-to-end path in order to make that local decision.

A host uses a default route when it has no more specific route for a destination. On an IPv4 host the default route is written 0.0.0.0/0; in IPv6 it is ::/0. The default gateway is the router address the host can reach on its local network. A host may reach devices in its own subnet directly at Layer 2, but sends traffic for other prefixes to the gateway. A missing or incorrect gateway commonly permits local communication while preventing access to remote networks.

When several routes match a destination, routers use longest-prefix match: the most specific matching network prefix is preferred. For example, a route to 10.20.0.0/16 is preferred over a default route for a destination in that network. If routes with the same prefix are available, metrics and implementation-specific selection rules help choose among them. Route preference and forwarding behavior should be verified on the platform being used rather than inferred only from a diagram.

Static routes are entered by an administrator. They are predictable and can suit small or stable networks, but must be updated when topology changes. Dynamic routing protocols exchange reachability information so routers can adapt to changes. OSPF is commonly used as an interior gateway protocol within an organization and calculates paths using link-state information. BGP exchanges reachability between autonomous systems and applies routing policy; it is central to interdomain Internet routing. These protocols have different scales, goals, and operational complexity.

A router may decrement the IPv4 time-to-live or IPv6 hop limit when forwarding. When it reaches zero, the packet is discarded and an ICMP time-exceeded message may be returned. Tools such as traceroute use this behavior to infer responding hops, but some routers filter or rate-limit these messages, so a missing hop does not prove that the path is broken. Ping tests reachability for ICMP; it does not test every application protocol or firewall rule.

Routing loops occur when routers' forwarding decisions send packets around a cycle. Hop limits bound how long such packets can circulate, but loops still waste capacity and cause outages. Dynamic protocols use convergence mechanisms to update paths after failures; during convergence, traffic may be interrupted or follow a suboptimal path. Redundant routes improve resilience only when the routing policy and physical design avoid shared failure points.

Troubleshooting should compare the host's address and prefix, gateway, and route table with the intended design. Test the gateway, then a remote address, and inspect the path when possible. On routers, check the route lookup for the exact destination and confirm the next-hop interface is operational. Firewall filtering, NAT, asymmetric paths, and DNS failures can look like routing problems, so isolate one layer and one direction at a time.
